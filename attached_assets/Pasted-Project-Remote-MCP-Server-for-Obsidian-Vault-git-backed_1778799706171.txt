Project: Remote MCP Server for Obsidian Vault (git-backed, Railway)

### i am interested in creating a remote MCP server for my obsidian vault , where claude.ai will be my agent that i can access remotely on my claude.ai /iOS phone  while the vault is on my local Desktop at home . i want to be able to access that vault even if my PC is off ..can you investigate if that can be done inspired by github repo @https://github.com/eddmann/obsidian-mcp

Architecture

Pattern: Git-backed. Vault lives in private GitHub repo, MCP server on Railway reads/writes via git operations.
Source of truth: GitHub. Desktop, Railway volume, and any future client are all caches.
PC-off requirement: Met. Service is independent of Desktop being on.

Vault & GitHub

PHI scope: Vault is 100% PHI-free (dev, learning, business ops only). No exclusions, push whole vault.
GitHub account: d2kole owns both repos (vault + MCP server code). Single PAT.

Sync (Obsidian Git Plugin)

Desktop: Auto-commit every 10 min, auto-push every 10 min, auto-pull on startup + every 5 min.
iOS Obsidian: Git plugin disabled. Mobile capture goes through Claude/MCP only. Single-writer pattern.

MCP Server Codebase

Base: Fork eddmann/obsidian-mcp (TypeScript, 18 tools, OAuth-ready, Streamable HTTP, surgical edit ops).
Modes: Both stdio (Desktop / Claude Code CLI — the reliable path) and HTTP+OAuth (remote / Claude.ai — best-effort).
Adaptation: Strip AWS CDK/Lambda/DynamoDB → Railway Dockerfile + persistent volume.

Railway Deployment

Plan: Hobby (~$5/mo).
Service: Single always-on Node web service, no cold starts.
Volume: 1GB persistent, mounted at /vault-cache, holds working tree across restarts.
Region: us-east4 (Virginia).

Auth

Model: Full OAuth 2.0 + PKCE (mandatory — claude.ai UI has no bearer-token field).
Primary reliable path: Claude Code CLI on Desktop (stdio or HTTP both work today).
Mobile via Claude.ai web/iOS: Best-effort. Known platform bugs (#155, #215, #46140, #228). Reconnect daily as needed. Reassess in 1–3 months.

Tool Surface

Reads: All read tools enabled, no path restrictions.
Writes: Scoped via OBSIDIAN_WRITE_PATHS to capture zones only. Tentative: 00-Inbox/,01-Daily/,Captures/,Journal/ (confirm exact folder names against vault at scaffold time).
Disabled: obsidian_execute_command (command-palette dispatch — too much blast radius).

Secrets & Ops

Secrets: Railway env vars only. GITHUB_PAT, OAUTH_CLIENT_SECRET, SESSION_ENCRYPTION_KEY, VAULT_REPO_URL. PAT and OAuth secret in Sealed Variables.
PAT scope: Fine-grained, vault repo only, 90-day expiry. Calendar reminder for rotation.
Logging: Structured JSON via pino to stdout → Railway log viewer.
Healthcheck: GET /healthz — verifies vault tree exists, git pull --dry-run works, session store reachable. Railway polls every 60s, auto-restarts on fail.
Alerting: Pushover ($5 one-time) on 3 consecutive healthz failures.

Disaster Recovery

Primary: Git history. Every Claude write is a revertable commit on GitHub.
Rate limiter: MAX_WRITES_PER_HOUR=20 server-side. Stops runaway tool calls before they become 200-commit cleanups.
Volume drill: Practice destroying and recreating the Railway volume once post-deploy. Confirms re-clone-from-GitHub recovery works.
PAT runbook: OPERATIONS.md in the server repo documenting revoke → reissue → update Sealed Var → restart. Practice once.
Not doing: Separate offsite backups, snapshot schedules. GitHub is the offsite backup.
